## 검사 범위

PDF 레이아웃/공통 지문/이어지는 페이지/답지 제외/체크포인트 재개/로그아웃 취소, AES-GCM과 소유자 바인딩, 제공자 순환·429·재시도·유료 차단, 중복 응답과 세션 스냅샷, 복수 개념과 단답 자기 채점, 실제 20×5 표준 문항 분할을 검사합니다.

임시 PostgreSQL 엔진에서 마이그레이션 전체를 적용하고 타 사용자 접근, 소유자 외래키, 작업 임대, 원자적 표준 가져오기, 플래시카드 검토 승격, 나중에 등록한 원본과 분석 연결, 편집/보관 상태 유지, 출처 개념의 버전 변경 시 적용 보류, 백업 복원 롤백과 기존 행 보존을 확인했습니다.

API 제공자 테스트는 주입된 전송 계층을 사용합니다. 무료 모델 메타데이터 200 응답을 실제 API 키의 인증/생성 성공으로 간주하지 않습니다.

## 실제 원격/브라우저 확인

- 승인된 Supabase 프로젝트에 표준 데이터 및 보존·복원 마이그레이션 적용.
- 7개 Edge Function 배포. 자료·AI 함수 6개는 인증 없는 실제 HTTP 요청을 모두 401로 거절했습니다.
- 사용자가 최초 계정을 생성했고 로그인된 홈의 주 메뉴 4개를 브라우저에서 확인했습니다.
- 공개 회원가입과 익명 로그인을 차단했으며 새로고침 후 설정을 확인했습니다.
- 서버 암호화 키를 Supabase Secrets에 등록했습니다. 진단에 포함된 초기 임시 키는 사용 전에 새 키로 교체했습니다. 현재 키는 소스와 파일에 보관하지 않습니다.
- Supabase 보안 진단: 경고/오류 없음. RLS 정책 없는 서버 전용 비밀 테이블 9개는 접근을 허용하지 않는 의도적인 구성입니다. 외래키 인덱스와 미사용 인덱스에 관한 정보성 항목이 남아 있습니다. [진단 설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
- 저장소 공개 전환과 GitHub Actions 게시 방식 설정을 사용자 추가 허용으로 적용했습니다. 사용자 PDF·DB·환경 파일·내부 검증 이미지는 소스 게시 대상에서 제외합니다.

## 실제 콘텐츠 검증 전제

사용자 PDF와 AI 키를 등록해야 실제 교재의 목차 분석 → 개념/문항 생성 → 교육적 검토 → 학습 → 원본 재풀이를 검증할 수 있습니다. 아직 이 전체 교재 흐름과 NVIDIA/Gemini 실제 생성 호출 성공을 주장하지 않습니다. 이를 대신하는 시연 데이터를 사용자 DB에 넣지 않습니다.

설정의 논리 JSON/CSV 백업에는 원본 파일, Auth, 비밀값, 생성/가져오기 작업이 포함되지 않습니다. JSON 복원은 같은 계정과 기존 비공개 Storage를 전제로 합니다.
