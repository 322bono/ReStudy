# RE:STUDY — AI 기반 PDF 학습 및 오답 관리 웹앱
## 기존 프로젝트 개선을 위한 전체 개발 명세

# 0. 개발 전 필수 지시

이미 개발 중인 RE:STUDY 프로젝트를 이어서 수정한다.

기존 코드, 데이터베이스, 사용자 계정, PDF 파일, 학습 기록, API 설정을 보존한다.

프로젝트를 처음부터 다시 생성하거나 기존 기능을 임의로 삭제하지 않는다.

새로운 요구사항과 기존 구현을 비교한 후 필요한 부분만 수정·확장한다.

이번 개발의 핵심은 다음 다섯 가지다.

1. PDF를 한 번 업로드하면 선택한 페이지 범위와 함께 영구 저장된다.
2. 최초에는 목차·단원별로 개념 정리와 기본 문제 은행을 구축한다.
3. 사용자가 오답을 등록하면 해당 문제와 연결된 개념 및 암기사항을 즉시 불러온다.
4. 일반 학습과 오답 노트에서 각각 개념 퀴즈 및 문제 은행을 이용할 수 있다.
5. AI API뿐 아니라 외부에서 생성한 표준 JSON 데이터를 붙여넣어도 동일하게 작동한다.

**AI는 콘텐츠를 생성하는 역할만 담당하며, 저장된 데이터의 처리·출제·채점·복습은 일반 프로그램 코드로 실행한다.**

# 1. 기술 구성

기존 기술 스택을 우선 유지한다.

프론트엔드:
- React + TypeScript + Vite
- Tailwind CSS
- shadcn/ui
- PDF.js
- Tesseract.js
- IndexedDB

백엔드:
- Supabase Auth
- Supabase PostgreSQL
- Supabase Storage
- Supabase Edge Functions

AI:
- NVIDIA NIM API
- Google Gemini API

배포:
- GitHub Pages
- GitHub Actions

Cloudflare나 별도의 호스팅 서비스를 추가하지 않는다.

PDF 텍스트 추출, OCR, 페이지 크롭, JSON 파싱, 문제 은행 검색, 객관식 채점은 가능한 한 브라우저에서 자체 처리한다.

API 요청은 인증된 Supabase Edge Function을 통해 수행한다.

등록된 NVIDIA·Gemini API 키는 서버 측에서 안전하게 보관하며, 로그인 후 자동으로 사용한다.

기본 AI 모드는 NVIDIA와 Gemini 자동 순환이며, 사용 가능한 모델과 제공자별 제한을 확인한다.

# 2. PDF 업로드 및 영구 저장

## 업로드 과정

1. PDF 선택
2. 전체 PDF 미리보기
3. 분석할 페이지 범위 선택
4. 목차 페이지 별도 지정
5. 과목 및 자료명 입력
6. 분석 방식 선택
7. 업로드 및 저장

### 페이지 범위

다음 방식을 지원한다.

- 전체 선택
- 시작~끝 페이지 선택
- 여러 구간 선택
- 개별 페이지 선택
- 특정 페이지 제외

예시:

분석 범위: `15-48, 62-90, 105-120`

목차 페이지: `3-6`

PDF의 실제 페이지 번호와 책에 인쇄된 페이지 번호를 구별한다.

### 영구 저장

원본 PDF 전체와 선택한 분석 범위, OCR 결과, 목차, 문제 인덱스, 개념 데이터, 문제 은행을 저장한다.

새로고침, 로그아웃, 다른 기기 로그인 후에도 그대로 유지되어야 한다.

원본 PDF는 Supabase Storage의 비공개 버킷에 저장한다.

사용자가 PDF를 삭제하지 않는 한 기존 학습 자료와 연결이 유지되어야 한다.

분석 범위를 변경하면 새 범위만 추가 처리하고 기존 기록은 보존한다.

### 분석 방식 선택

- AI 자동 분석
- 외부 AI 분석 결과 가져오기
- 나중에 분석

어떤 방식을 선택해도 원본 PDF는 먼저 저장할 수 있어야 한다.

# 3. PDF 자체 처리 및 OCR

PDF.js와 Tesseract.js를 사용한다.

처리 순서:

1. PDF 텍스트 레이어 추출
2. 필요한 페이지에만 Tesseract.js OCR 실행
3. 페이지별 텍스트와 위치 저장
4. 목차 및 단원 구조 인식
5. 문제 번호와 페이지 위치 인덱싱
6. 결과 저장

문제 번호 인덱싱은 개념 분석과 별개다.

최초 업로드 시 모든 문항을 AI로 분석하지 않는다.

문제별 크롭 좌표만 미리 인식하거나, 오답 등록 시 해당 문항을 찾아 크롭한다.

수식·그래프·표는 OCR이 잘못 인식할 수 있으므로 원본 PDF 이미지를 보존한다.

문제 경계가 잘못 인식되면 사용자가 직접 크롭 영역을 수정할 수 있어야 한다.

# 4. 최초 PDF 분석 — 목차와 개념 중심

PDF를 처음 등록하면 전체 문제를 심층 분석하지 않는다.

대신 선택한 범위의 단원 구조와 핵심 개념을 정리한다.

## 목차 분석

목차를 통해 다음 구조를 생성한다.

과목 → 대단원 → 중단원 → 소단원 → 세부 개념

사용자가 분석된 목차와 페이지 범위를 수정할 수 있어야 한다.

## 개념 정리

단원별로 다음 정보를 생성하고 저장한다.

- 개념 이름
- 핵심 정의
- 필수 공식
- 중요한 성립 조건
- 암기사항
- 자주 발생하는 오개념
- 관련 개념과 차이점
- 간단한 예시
- 원본 PDF 출처 페이지

단순히 목차 제목만 분석한 경우에는 교과서의 실제 본문을 분석한 것처럼 표시하지 않는다.

필요하다면 해당 단원의 개념 설명 페이지를 추가 분석한다.

## 기본 문제 은행 생성

최초 분석 시 단원별 기본 문제를 생성한다.

기본값:
- 개념 퀴즈 5문제
- 기본 연습문제 5문제

문제 수는 변경할 수 있어야 한다.

생성된 문제는 모두 영구 저장되며 이후 AI 호출 없이 사용할 수 있어야 한다.

# 5. 문제 은행 — 핵심 기능

**문제 은행은 앱 전체에서 가장 중요한 학습 기능 중 하나다.**

단순한 AI 문제 생성 화면이 아니라, 문제를 저장·분류·검색·조합·출제·채점·재학습할 수 있는 완전한 시스템으로 구현한다.

## 5.1 문제 은행 구성

문제 은행은 다음 세 종류로 구분한다.

### A. 단원별 문제 은행

문제집이나 교과서의 목차를 기준으로 생성한다.

예시:

공통수학2 → 함수 → 일대일대응

해당 개념에 연결된 모든 개념 퀴즈와 연습문제를 확인할 수 있어야 한다.

### B. 오답 연계 문제 은행

사용자가 틀린 문제에 연결된 개념의 문제만 모은다.

예시:

오답: 47번

관련 개념:
- 일대일함수
- 일대일대응
- 치역과 공역

이 세 개념과 관련된 개념 퀴즈, 연습문제, 유사문제를 자동으로 모은다.

### C. 사용자 지정 문제 은행

여러 과목 자료 또는 단원을 선택하여 직접 문제 세트를 구성한다.

예시:

통합사회2
- 시장 실패
- 외부 효과
- 공공재
- 정부의 시장 개입

위 네 개념을 선택하면 관련 문제를 하나의 학습 세트로 구성한다.

# 6. 문제 은행의 문제 종류

다음 문제 유형을 지원한다.

### 객관식
- 4지선다 및 5지선다
- 정답 1개
- 그럴듯한 오답 선택지
- 선택지별 해설

### OX
- 정확한 개념 판단
- 애매한 서술 지양
- 정답과 근거 제공

### 빈칸 채우기
- 핵심 용어
- 공식
- 정의
- 암기사항

### 단답형
- 짧은 개념 설명
- 조건
- 용어
- 수치 또는 공식

### ㄱ, ㄴ, ㄷ 판단형
- 여러 명제의 참·거짓 판단
- 실제 내신 형태의 조합 선택지

### 개념 적용형
- 단순 암기보다 실제 이해도 확인
- 조건 변경
- 반례 판단
- 여러 개념 비교

### 자료 해석형
- 텍스트로 재구성 가능한 표나 자료 사용
- 필요한 경우 원본 이미지와 연결
- 실제 존재하지 않는 그림을 임의로 참조하지 않음

문제 유형은 데이터에 따라 구별하고, 별도의 AI 호출 없이 일반 코드로 문제를 렌더링한다.

# 7. 문제 은행 생성 및 관리

## 기본 문제 자동 생성

PDF 최초 등록 시 단원별 문제를 생성한다.

이미 생성된 문항이 있다면 중복 생성하지 않는다.

## 추가 문제 생성

사용자가 특정 단원 또는 개념을 선택하면 원하는 문제 수만큼 추가 생성할 수 있어야 한다.

예시:

범위: 함수

문제 수: 30개

난이도:
- 하 20%
- 중 50%
- 상 30%

문제 유형:
- 객관식 15
- OX 5
- 빈칸 5
- 단답형 5

요청한 유형과 난이도 비율을 최대한 반영한다.

## 100문제 문제 은행

특정 단원 또는 여러 개념을 선택하여 100문제짜리 문제 은행을 구성할 수 있어야 한다.

AI 응답 길이와 API 제한을 고려해 기본적으로 20문제씩 5개 작업으로 분할한다.

각 작업은 독립적으로 저장하고 실패한 작업만 재시도한다.

외부 AI로 생성한 100문제도 동일한 방식으로 가져올 수 있어야 한다.

## 문제 중복 방지

다음 정보를 이용해 중복을 검사한다.

- 정규화된 문제 본문
- 선택지
- 관련 개념
- 문제 유형
- 기존 문제와의 내용 유사성

완전히 같은 문제는 중복 등록하지 않는다.

문장이 다르지만 개념과 풀이가 유사한 문항은 무조건 삭제하지 않고 유사 문항으로 관리한다.

## 문제 수정

문제 은행의 각 문항에 대해 다음 작업을 제공한다.

- 문제 수정
- 선택지 수정
- 정답 수정
- 해설 수정
- 난이도 변경
- 관련 개념 변경
- 문제 삭제
- 문제 재생성
- 검토 필요 표시

사용자가 수정한 문항은 AI가 자동으로 덮어쓰지 않는다.

# 8. 문제 은행 학습 모드

문제 은행에서는 실제 시험처럼 문제를 풀 수 있어야 한다.

## 문제 세트 구성

사용자가 선택할 수 있는 항목:

- 과목
- 자료
- 단원
- 세부 개념
- 문제 유형
- 난이도
- 문제 수
- 출제 범위

### 출제 방식

- 순서대로
- 무작위
- 아직 풀지 않은 문제 우선
- 이전에 틀린 문제 우선
- 취약 개념 우선
- 여러 난이도 혼합

이미 저장된 문제 중 조건에 맞는 문항을 선택한다.

문제 수가 부족한 경우 자동으로 AI를 호출하지 않고 기존 문항 수를 안내한 뒤 추가 생성을 선택할 수 있게 한다.

## 문제 풀이 화면

화면 중앙에 문제를 표시한다.

- 문제 번호
- 본문
- 선택지 또는 답안 입력
- 이전/다음 문제
- 답안 제출
- 풀이 진행률

문제를 푸는 동안 정답과 해설은 숨긴다.

## 채점

객관식과 OX는 저장된 정답을 기준으로 채점한다.

단답형과 빈칸은 허용 정답 및 정규화 규칙을 활용한다.

의미가 같지만 표현이 다른 답변은 무조건 틀린 것으로 단정하지 않도록 자기 채점 또는 검토 기능을 제공한다.

서술형 의미 평가가 필요한 경우에만 AI를 선택적으로 활용한다.

## 결과 화면

세트 완료 후 다음을 보여준다.

- 총 문제 수
- 정답 수
- 오답 수
- 정답률
- 틀린 문제 목록
- 취약 개념
- 해설 확인
- 틀린 문제 다시 풀기

문제 은행에서 틀린 문제는 별도로 기록하고, 원본 문제집 오답과 구분하면서도 관련 개념 학습 기록에 함께 반영한다.

## 재학습

사용자가 다음 옵션을 선택할 수 있어야 한다.

- 틀린 문제만 다시 풀기
- 관련 개념 복습
- 비슷한 문제 풀기
- 다음 복습에 추가

# 9. 오답 등록 및 문제별 분석

사용자가 문제집에서 틀린 문제 번호를 입력한다.

예시:

문제집: 공통수학2

오답: 17, 24, 36, 47

앱은 각 번호에 대응하는 원본 문제를 찾는다.

단원마다 번호가 반복된다면 단원과 페이지로 구별한다.

## 저장된 분석 데이터 우선

각 오답 등록 시 다음 순서로 처리한다.

1. 문제 인덱스 검색
2. 해당 문제의 기존 분석 데이터 조회
3. 관련 개념과 암기사항 조회
4. 이미 저장되어 있다면 즉시 표시
5. 데이터가 없을 때만 분석 방식 선택

분석 방식:
- NVIDIA/Gemini 자동 분석
- 외부 AI 분석 결과 가져오기

오답을 등록할 때마다 무조건 API를 호출하면 안 된다.

## 문제별 심층 분석

아직 분석하지 않은 문제에는 다음 데이터를 생성한다.

- 관련 개념
- 필수 암기사항
- 핵심 공식
- 중요한 조건
- 자주 발생하는 오개념
- 문제 해결의 핵심
- 예상되는 실수
- 비슷한 문제 유형
- 유사 연습문제

사용자의 실제 풀이를 확인하지 않았다면 왜 틀렸는지 단정하지 않는다.

분석 결과는 해당 문제에 영구 저장한다.

---

# 10. 오답 노트 전용 문제 은행

**일반 문제 은행과 오답 노트 내 문제 은행을 반드시 연결한다.**

오답 노트에서는 사용자가 틀린 문제와 관련된 내용만 집중해서 학습할 수 있어야 한다.

## 개별 오답 상세 화면

예시:

공통수학2 · 47번

관련 개념:
- 일대일함수
- 일대일대응
- 치역과 공역

암기사항:
- 일대일대응은 치역과 공역이 같아야 함

메뉴:
- 개념 정리
- 암기하기
- 개념 퀴즈
- 관련 문제 은행
- 유사문제
- 원본 다시 풀기

### 개념 퀴즈

47번에 연결된 개념의 문제만 출제한다.

기본 5문제.

### 관련 문제 은행

47번의 관련 개념을 기반으로 기존 문제 은행을 검색한다.

사용자가 문제 수와 난이도를 선택할 수 있다.

### 유사문제

47번과 같은 개념 및 풀이 사고 과정을 활용하는 새로운 유형의 문제를 제공한다.

기존에 생성된 유사문제가 있으면 재사용한다.

부족한 경우에만 추가 생성을 요청할 수 있다.

## 여러 오답 동시 복습

사용자가 오답을 여러 개 선택하면 관련 개념을 통합한다.

예시:

47번 → 일대일함수, 일대일대응

53번 → 일대일대응, 치역과 공역

61번 → 치역과 공역

중복 개념을 제거하여 하나의 복습 범위를 만든다.

이 범위를 바탕으로 개념 퀴즈 및 문제 은행 세트를 구성한다.

문제는 기존 문제 은행에서 선택하므로 추가 AI 호출이 필요 없다.

## 복습 결과 연결

오답 전용 문제 은행에서 학습한 결과는 다음에 반영한다.

- 해당 원본 오답의 관련 개념 이해도
- 개념별 정답률
- 취약 개념 순위
- 복습 일정

단, 개념 퀴즈 정답과 원본 문제 재풀이 정답은 서로 다른 기록으로 보존한다.

- 원본 문제 크롭 표시

- 지우개

원본 PDF에 존재하는 문항을 그대로 표시해야 한다.

iPad와 Apple Pencil 입력도 고려한다.

## 표준 JSON 규칙

- `schema_version`은 `"restudy.v1"`
- 모든 최상위 필드는 필수
- 데이터가 없는 컬렉션은 `[]`
- `document_id`와 `job_id`는 사이트가 발급
- `part`, `total_parts`는 1부터 시작하는 정수
- `chapter_id` 및 `concept_ids`는 실제 존재하는 개념과 단원을 참조
- 다른 분할에서 먼저 등록한 개념 ID도 참조 가능
- 페이지 번호는 PDF 실제 페이지 기준, 1부터 시작
- `kind`: `mcq`, `ox`, `short`, `blank`
- `purpose`: `concept`, `practice`, `similar`
- `level`: `easy`, `medium`, `hard`
- 객관식 `answer`: A~E, 실제 선택지 범위 내 값
- OX `answer`: O 또는 X
- 단답형·빈칸 `answer`: 문자열
- `accepted_answers`: 허용되는 다른 정답 문자열 배열
- `source_problem`: 일반 문제는 null, 오답 유사문제는 원본 문제 식별 객체
- `source_pages`: 근거가 되는 PDF 페이지 번호 배열
- `option_explanations`: 선택지별 설명 객체, 해당하지 않으면 {}
- `similarities`: 원본 문제 식별 객체 `a`, `b`, 유사도 `score`(0~1), 근거 `reason`을 가진 객체의 배열
- 문제 ID는 문서 및 작업 내에서 충돌하지 않아야 함

문제 은행 데이터는 반드시 원본 문제의 이미지와 별도로 관리한다.

`purpose`는 활용 목적이고 `kind`는 문제 형식이므로 혼동하지 않는다.

AI 생성 데이터에 오류가 있을 수 있으므로 형식 검증과 내용 검토 상태를 구분한다.

# 14. 외부 AI 분석 결과 가져오기

NVIDIA와 Gemini API의 한도가 초과되거나 사용자가 직접 외부 AI를 이용하려는 경우를 지원한다.

**이 기능은 사이트 내부에서 별도의 AI 호출 없이 작동해야 한다.**

## 화면 구성

### ① 프롬프트 복사

표시 문구:

"아래 프롬프트를 복사하세요."

[프롬프트 복사]

사이트는 현재 선택한 자료를 기준으로 프롬프트를 자동 생성한다.

프롬프트에 포함할 정보:
- 문서 ID
- 작업 ID
- 과목 및 자료명
- 선택된 페이지 범위
- 목차 정보
- 분석할 문항
- 생성할 문제 수
- 문제 유형 및 난이도
- 정확한 전체 JSON Schema

### ② 외부 AI에서 분석

표시 문구:

"같은 문제집 PDF를 ChatGPT 등에 첨부하고 복사한 프롬프트를 입력하세요."

선택한 페이지 범위만 PDF로 내보낼 수 있도록 한다.

### ③ 결과 붙여넣기

표시 문구:

"출력된 값을 그대로 복사하여 아래에 붙여넣으세요."

[분석 결과 붙여넣기]

[데이터 등록]

## 처리 과정

JSON 입력을 받으면 사이트는 다음을 직접 실행한다.

1. JSON 코드 블록 마커 제거
2. JSON 파싱
3. Zod 및 JSON Schema 검증
4. 문서 ID 일치 확인
5. 작업 ID 확인
6. 참조된 단원 및 개념 확인
7. 문제 번호·페이지 범위 검증
8. 정답 및 선택지 형식 검증
9. 기존 데이터와 중복 검사
10. 가져오기 미리보기
11. 사용자 확인 후 DB 저장
12. 문제 은행·개념·오답·암기 기능에 자동 연결

**이 과정에서 NVIDIA, Gemini 등 어떤 AI API도 호출하지 않는다.**

API 분석 결과도 동일한 검증 및 저장 코드를 사용한다.

# 15. 외부 AI용 프롬프트 자동 생성

사이트는 다음 템플릿을 이용하여 실제 분석 프롬프트를 생성한다.

```text
당신은 RE:STUDY 표준 학습 데이터 생성기입니다.

첨부된 PDF를 분석하여 restudy.v1 형식의
JSON 데이터를 생성하세요.

문서 ID: {{document_id}}
작업 ID: {{job_id}}
자료명: {{document_title}}
과목: {{subject}}
분석 범위: {{selected_pages}}
목차: {{chapters}}
분석할 문제: {{target_questions}}
요청 작업: {{task_type}}
생성 문제 수: {{question_count}}
문제 유형: {{question_types}}
난이도 구성: {{difficulty_distribution}}

필수 요구사항:

1. 실제 PDF 내용과 지정된 범위를 기준으로 분석하세요.
2. 개념 정의, 공식, 암기사항, 오개념을 정리하세요.
3. 문항별 분석이 요청된 경우 해당 문항에
   연결된 개념과 암기사항을 작성하세요.
4. 문제 은행을 요청했다면 지정된 문제 수와
   유형 및 난이도에 맞춰 새 문제를 제작하세요.
5. 모든 문제에는 정답과 해설을 포함하세요.
6. 객관식에는 선택지별 해설도 포함하세요.
7. 개념 및 단원의 참조 ID를 정확히 일치시키세요.
8. 원본 자료에 없는 사실을 확인된 사실처럼
   만들어내지 마세요.
9. 반드시 아래 JSON Schema를 따르세요.
10. JSON 이외의 설명은 출력하지 마세요.
11. 출력 한도에 도달하면 완성된 분할 데이터만
    출력하고, 나머지는 다음 분할에서 생성하세요.
12. 이전에 생성한 문항과 중복되지 않게 하세요.

JSON Schema:
{{FULL_JSON_SCHEMA}}

현재 분할: {{part}}
전체 분할: {{total_parts}}
```

`FULL_JSON_SCHEMA`는 실제 구현된 전체 스키마를 자동 삽입한다.

문제 은행 100문제 생성 시에는 분할마다 같은 문서 ID와 작업 ID를 유지한다.

# 16. 문제 은행 100문제 외부 가져오기

대량 문제 생성에는 분할 가져오기를 지원한다.

기본값:
- 전체 100문제
- 분할당 20문제
- 총 5개 분할

각 결과에는 동일한 `document_id`, `job_id`가 포함되어야 한다.

`part`와 `total_parts`를 통해 분할을 구별한다.

사용자가 각 결과를 차례로 또는 순서에 관계없이 붙여넣으면 사이트가 자동으로 병합한다.

예시 진행 상태:

문제 은행 가져오기

- 1/5 완료 · 20문제
- 2/5 완료 · 40문제
- 3/5 완료 · 60문제
- 4/5 완료 · 80문제
- 5/5 완료 · 100문제

분할마다 JSON을 파싱하고 검증한다.

이전에 등록한 단원·개념 ID는 새 분할에서도 참조 가능해야 한다.

아직 등록되지 않은 ID에 대한 참조는 누락 여부를 표시하고, 모든 분할을 합친 후 최종 검증한다.

동일 분할을 다시 붙여넣어도 중복 저장되지 않아야 한다.

문제 100개가 완료되면 일반 문제 은행과 오답 연계 문제 은행에서 즉시 활용할 수 있어야 한다.

# 17. API 및 수동 가져오기 공통 구조

자동 분석:

NVIDIA / Gemini
→ restudy.v1 JSON
→ 검증
→ 저장
→ 문제 은행 및 개념 연결

수동 분석:

ChatGPT 등 외부 AI
→ restudy.v1 JSON
→ 사용자가 붙여넣기
→ 동일한 검증
→ 동일한 저장
→ 동일한 문제 은행 및 개념 연결

**데이터의 생성 경로는 학습 기능에 영향을 주면 안 된다.**

이미 저장된 데이터가 있으면 새로운 AI 요청 없이 다음 기능이 작동해야 한다.

- 개념 정리

1일 → 3일 → 7일 → 14일

# 22. 최종 완료 조건

다음 기능이 실제로 작동해야 한다.

- PDF 영구 저장
- 페이지 범위 선택
- 자체 OCR
- 목차별 개념 정리
- 목차별 개념 퀴즈
- 단원별 문제 은행
- 100문제 대량 생성
- 문제 은행의 실제 출제 및 채점
- 오답 등록 후 기존 JSON 자동 연결
- 오답 전용 개념 퀴즈
- 오답 전용 문제 은행
- 유사문제 생성 및 활용
- 깨끗한 원본 문제 재풀이
- NVIDIA/Gemini 자동 순환
- API 사용 불가 시 외부 JSON 가져오기
- JSON 가져오기 과정에서 AI 호출 없음
- 전체 학습 기록 영구 저장

기능이 없는 버튼이나 가짜 데이터를 사용하지 않는다.

**최종 목표는 문제집 PDF와 학습 개념을 하나의 데이터베이스에 연결하고, 일반 학습과 오답 복습 모두에서 문제 은행을 자유롭게 활용할 수 있는 실제 학습 앱을 완성하는 것이다.**

기존 프로젝트를 분석하고 이 명세에 맞춰 실제 구현과 테스트까지 수행하라.
