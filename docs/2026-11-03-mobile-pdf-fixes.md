# 2026-11-03 PDF·모바일·불러오기 수정

요청: Safari PDF 인식 예외, 선택한 PDF 범위 탐색, 지울 수 없는 숫자 입력, 모바일 추가 메뉴와 복잡한 자료 화면, 반복되는 원본 로딩을 해결한다.

## 원인과 변경

- PDF.js 6.4.299 legacy도 `ReadableStream`에 `for await`를 사용한다. 해당 반복 기능이 없는 Safari 환경을 재현하면 네이티브 텍스트 PDF부터 실패한다. 메인과 별도 Worker 양쪽에 스트림 반복 호환 처리를 적용하고 Worker 캐시 URL을 갱신한다. 실제 읽기 오류는 숨기지 않는다.
- 원본 PDF 쪽번호와 분석 결과 배열 길이를 섞어 쓰던 탐색을 분리한다. `PDF 73쪽`과 `분석 1 / 28쪽`은 서로 다른 값이다. 누락 쪽과 여러 범위 사이에서는 저장된 실제 쪽번호로 이동한다.
- 숫자를 입력할 때마다 최솟값으로 바꾸지 않는다. 빈 초안을 유지하고 blur/Enter에서 유효 숫자만 확정한다.
- 모바일 추가 메뉴의 blur 닫기는 터치 클릭을 취소할 수 있으므로 명시적인 열림 상태와 바깥 pointerdown으로 대체한다. 자료 화면의 제목·작업 버튼을 세로로 분리하고 인식 관리·목차 편집은 범위·설정에 모은다.
- API 상태는 저장된 개념·문제·카드 개수와 현재 결과를 우선 표시한다. 호출 내역은 접힌 목록에 모델·소요 시간·성공 여부·HTTP 상태를 표시한다. 이전 작업이 완료되었어도 새 요청의 오류를 숨기지 않는다.
- 이미지마다 `auth.getUser()`를 요청하던 경로를 로컬 세션 기반 캐시 구분으로 바꾼다. 최초 다운로드의 서버 인증·소유권 검사는 유지한다. 동시 요청을 합치고 다운로드한 이미지도 메모리에 보관한다. 계정 전환·로그아웃 시 폐기하며 같은 계정의 토큰 갱신은 사용 중인 blob을 깨뜨리지 않는다.
- 저장된 페이지 PNG를 먼저 사용하고 전체 PDF 렌더링은 실패 복구에만 사용한다. 인접 페이지와 다음 복습 문항을 제한된 동시성으로 미리 가져온다. 캐시는 미사용 이미지부터 제한하고 사용 중인 이미지 URL은 해제할 때까지 보존한다.
- 원본 재풀이의 해설을 선택한 세션 단위로 미리 읽는 별도 `solve/:id/answer-keys` 경로를 추가한다. 스냅샷에 포함된 문항만 반환하며 기록을 쓰거나 채점하지 않는다. 화면에는 정답 확인을 누른 뒤 표시한다.
- API 작업 상태를 두 군데서 중복 조회하지 않는다. 전체 학습 상태는 새 처리 단위가 저장될 때 갱신한다.

## 검증 범위

실제 PDF 생성·텍스트 추출·렌더링·크롭의 픽셀과 별도 Worker 실행을 통해 스트림 반복 미지원 환경을 검사한다. 탐색 범위·빈 숫자 입력·동시 이미지 요청·캐시 만료·계정 전환·로그아웃·수정된 크롭·세션별 일괄 해설 조회를 회귀 검사한다.

실제 iPhone/iPad Safari 동작은 브라우저 제어가 가능한 환경에서 별도로 확인해야 한다. 자동 검사만으로 실기기 확인을 했다고 표시하지 않는다.
