# 사전 콘텐츠 파일 형식

관리 화면의 **빈 JSON 템플릿**은 현재 등록한 원본의 문제 ID·번호·페이지를 포함합니다. 여기에 준비한 개념과 문제 은행을 채워 **검사·미리보기 → 검사한 콘텐츠 가져오기**로 저장합니다. 파일을 읽는 것만으로는 DB가 바뀌지 않습니다.

## 항목

| 항목 | 의미 |
|---|---|
| schemaVersion | 현재 형식은 1 |
| concepts | 계층형 개념·정의·성질·오개념 |
| items | 사전에 작성한 확인 문항·정답·해설 |
| mappings | 원본 문제와 개념의 다대다 연결, 선택적인 원본 답안 |
| materials | 원본 파일의 참조 정보. PDF 자체는 포함하지 않음 |

개념·은행 문항 ID는 수정 후에도 유지합니다. 문자·숫자·밑줄·하이픈을 사용할 수 있으며, 슬래시나 공백은 사용할 수 없습니다. 같은 ID를 가져오면 그 항목만 갱신합니다. 파일에 생략한 기존 콘텐츠나 학습 기록은 삭제하지 않습니다.

## 개념

`id`, `subject`, `major`, `minor`, `name`, `definition`으로 **과목 → 대단원 → 소단원 → 세부 개념**을 구성합니다. `properties`는 성질 문자열 목록입니다. `misconceptions`는 `{id, label, correction}` 목록입니다. `sources`는 `{materialId, page}` 목록이며 페이지는 1부터 셉니다.

## 은행 문항

필수 값은 `id`, `conceptId`, `type`, `prompt`, `answer`, `explanation`입니다.

- type: 객관식 / OX / 빈칸 / 단답형 / 서술형 / 플래시카드 / 문장 가리기
- choices: 객관식 선택지 문자열 목록. OX는 정확히 `["O", "X"]`
- answer: 준비한 정답. 객관식/OX는 choices의 실제 문자열과 같아야 함
- acceptedAnswers: 단답·빈칸에서 허용할 추가 정답 문자열. 의미 해석 없이 공백·유니코드 정규화만 비교
- choiceFeedback: 선택지 문자열을 키로 하는 `{explanation, misconceptionTag}`. 오답 선택지마다 교정 해설 또는 공통 correction이 필요함
- correction: 개념 교정 설명
- difficulty: 기본 / 보통 / 심화
- modes: quiz / memory / check 중 하나 이상. 암기용 카드는 memory에 체크
- sources: 근거가 되는 실제 자료 ID와 페이지. 비어 있으면 개념의 sources를 사용
- active: false이면 새 학습에서 제외. 과거 기록은 유지

서술형은 제출 후 저장된 정답과 해설을 보여 주고 직접 맞힘/틀림을 고릅니다. 앱이 답변의 의미를 평가하지 않습니다. 문장 가리기·빈칸은 작성자가 prompt에 가린 부분과 문맥을 준비하고 answer에 펼칠 내용을 입력합니다.

자료 선택 학습은 해당 자료·페이지 안에 **모든 출처가 포함되는 문항**만 출제합니다. 출처가 없는 일반 개념 문항은 원본 문제에 직접 연결한 개념 복습에서는 사용할 수 있지만, 자료 선택 학습의 근거로 임의 배정하지 않습니다.

## 원본 연결

문제마다 여러 개념 ID를 연결할 수 있습니다. 아래 둘 중 하나로 원본 문항을 지정합니다.

```json
{"questionId":"템플릿의_실제_문제_ID","conceptIds":["concept_id"]}
```

```json
{"materialId":"템플릿의_실제_자료_ID","number":47,"page":3,"conceptIds":["concept_id"],"answer":"등록할 원본 정답","explanation":"등록할 원본 해설"}
```

같은 번호가 반복되면 페이지까지 정확히 지정합니다. 자료·번호·페이지로도 구별되지 않으면 questionId를 사용합니다. 원본 답안을 등록하지 않아도 자기 채점은 가능하며 앱이 원본 정답을 추측하지 않습니다.

## 빈 전체 형식

```json
{"schemaVersion":1,"concepts":[],"items":[],"mappings":[],"materials":[]}
```

이것은 구조 안내이며 학습용 시드 데이터가 아닙니다. 관리 화면에서 실제 콘텐츠를 입력하거나 별도로 검토한 데이터를 가져와야 합니다.

## SQLite

**SQLite 내보내기**는 `content_meta`, `concepts`, `bank_items`, `mappings` 테이블을 가진 콘텐츠 전용 파일입니다. 같은 앱의 내보낸 파일을 JSON과 동일하게 검사하고 가져올 수 있습니다. 사용자 전체 데이터베이스(`re-local.sqlite`)는 학습 이력까지 포함하므로 콘텐츠 가져오기 파일로 쓰지 않습니다.

원본 자료는 별도로 먼저 등록해야 합니다. 다른 PC로 옮길 때는 원본·기록을 포함한 `data` 폴더 전체를 백업하거나, 새로 등록한 자료 ID에 맞게 출처·매핑 참조를 수정한 뒤 검사하세요.

## 검사와 수정

중복 ID, 존재하지 않는 개념/자료/페이지, 정답·선택지 불일치, 과목 불일치, 잘못된 원본 연결은 가져오기 전에 오류로 표시합니다. 한 오류라도 있으면 전체 저장을 취소합니다. 문항 수 부족, 출처 미지정, 미정의 오개념 태그 등은 경고로 표시합니다.

개념·은행·매핑 수정은 기존 학습 세션을 다시 채점하지 않습니다. 시작 당시 문항·개념 설명·정답·해설·원본 이미지 스냅샷을 보관합니다. 개념 매핑을 바꾸면 새 개념의 이해도는 다시 확인해야 합니다.
