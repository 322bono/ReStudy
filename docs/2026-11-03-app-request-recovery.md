# 앱 요청 지연·중단 복구

실제 서버 로그에서 app v14의 HTTP 546 `WORKER_RESOURCE_LIMIT`, HTTP 500, Worker 종료 사유 `WallClockTime`을 확인했다. PostgreSQL은 정상 응답했고 잠금 대기는 없었다.

원본 이미지 한 장의 서명 URL을 요청할 때도 `document_pages` 전체를 `select('*')`로 읽고 있었다. 저장된 169쪽의 OCR 본문·좌표 JSON 합계는 약 9.86MB였다. 페이지·문항 미리 불러오기와 결합하면 같은 내용을 여러 요청에서 반복 전송한다. 학습·복습의 `state(ctx, true)`에도 전체 좌표가 포함됐다.

## 수정

- 페이지 이미지: 소유자·문서 ID·실제 PDF 쪽수로 조회한다.
- 문항 이미지: 소유자·문항 ID의 저장된 크롭 경로와 해당 출처 페이지 정보만 조회한다.
- 학습 상태: 페이지 분류·크기·본문 등 필요한 필드만 투영한다. 무거운 OCR 좌표는 일반 학습 요청으로 읽지 않는다.
- OCR 원본, 크롭 이미지, 콘텐츠 ID, 학습 기록, 백업 경로는 보존한다.
- 소유권 검사와 정답·해설 페이지 차단은 유지한다.

회귀 검사는 이미지 조회의 문서·쪽수·소유자 범위, OCR 좌표 제외, 저장 데이터 보존, 정답 페이지 거절을 확인한다. app v15로 서버에 적용했다. 실제 계정의 복구 여부는 배포 후 요청 로그 및 사용자 재현으로 확인한다.
